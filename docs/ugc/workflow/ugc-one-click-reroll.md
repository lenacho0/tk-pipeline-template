# UGC 一键覆盖重生成 9宫格

## 当前口径

UGC 9宫格重生成已改为**一键覆盖模式**：

1. 用户在 `UGC-04 6宫格分镜表` 找到要重生的记录。
2. 勾选 `一键重生成9宫格`。
3. 本地触发器执行后，直接重新生成当前记录的 9宫格图片。
4. 新图片覆盖当前 UGC-04 记录中的旧结果字段。
5. 系统自动重新切分 UGC-05 单张分镜图：如果已有同一 UGC-04 + 分镜序号的 UGC-05 记录，则覆盖更新；如果没有，则创建。
6. 系统自动复位 `一键重生成9宫格`。

旧的候选池 / 多字段触发方案已经从飞书 Base 删除，不再作为日常入口。

## 用户操作

打开：

- `UGC-04 6宫格分镜表`
- 视图：`01-一键重生成`

只需要操作一个字段：

- `一键重生成9宫格`：勾选即可。

不用填写：

- 重新生成数量
- 重新生成请求
- 重新生成执行状态
- 候选状态
- 候选序号
- 重生成组ID

这些旧字段已删除。

## 系统字段

UGC-04 保留的一键字段：

| 字段 | 用途 |
| --- | --- |
| `一键重生成9宫格` | 用户触发入口；勾选后等待触发器处理 |
| `一键重生成状态` | 系统写入：`处理中` / `成功` / `失败` |
| `一键重生成结果` | 系统写入本次执行摘要 JSON |

python3 tk_ugc_reroll_trigger.py --stage grid --limit 20

`--call-models` 是安全闸门：没有它就不会真实调用图片模型。

## 覆盖字段

一键重生成成功后会覆盖当前 UGC-04 记录的：

- `6宫格生成状态`
- `6宫格图片`
- `6宫格图片URL`
- `6宫格图片file_token`
- `错误信息`

同时会同步处理 UGC-05：

- 按新 9宫格重新裁切 active panels
- 覆盖同一 `关联6宫格任务 + 分镜序号` 的旧 UGC-05 记录
- 更新 `原始裁切图片`、`原始裁切图片路径`、`原始裁切图片file_token`、`裁切状态`
- 如果不存在对应 UGC-05 记录，则创建新记录

高清化和视频生成现在走 UGC-05 人工确认入口。相关单选字段已补全选项：

- `分镜图审核状态`：`待确认` / `通过` / `不通过`
- `分镜图操作`：`不触发` / `确认分镜图并高清化` / `重新生成单张分镜图`
- `分镜图执行状态`：`待处理` / `处理中` / `成功` / `失败`
- `高清图审核状态`：`待确认` / `通过` / `不通过`
- `高清图操作`：`不触发` / `生成分镜视频` / `重新高清化`

用户操作：

- 在 `01-分镜图确认` 视图里，确认单张分镜图 OK 后，设置：`分镜图审核状态=通过`、`分镜图操作=确认分镜图并高清化`。
- 如果某一张分镜图不满意，在该 UGC-05 行设置：`分镜图操作=重新生成单张分镜图`，可在 `分镜图备注` 写原因。系统只重绘这一张，并把它重新置为 `分镜图审核状态=待确认`，不会影响其他分镜图。
- 系统高清化成功后会写入 `高清分镜图`，并设置 `高清图审核状态=待确认`。
- 在 `02-高清图确认` 视图里，确认高清图 OK 后，设置：`高清图审核状态=通过`、`高清图操作=生成分镜视频`。
- 系统会创建 UGC-06 并运行图生视频。
- UGC-06 视频生成成功后会进入 `分镜视频审核状态=待确认`。
- 如果某一条分镜视频不满意，在 `UGC-06 分镜视频表` 的 `04-分镜视频审核与重生` 视图里，对该行设置：`分镜视频操作=重新生成分镜视频`，可在 `分镜视频备注` 写原因。系统只覆盖重生这一条 UGC-06 视频，不会影响其他分镜视频。
- UGC-06 相关单选字段已补全选项：`分镜视频审核状态=待确认/通过/不通过`、`分镜视频操作=不触发/生成分镜视频/重新生成分镜视频`、`分镜视频执行状态=待处理/处理中/成功/失败`。

暂不会自动重跑 UGC-07 成片；成片合成仍建议等所有 UGC-06 分镜视频确认后再执行。
