- 本轮讨论后的关键结论：不能简单把所有脚本都强制要求 `speaker`，否则会误伤本来就应该是旁白或静默镜头的内容；更合理的统一结构化方案是为每个脚本片段增加 `content_type`，固定为三类：`dialogue`（角色出镜说话）、`voiceover`（旁白/内心音/画外音）、`silent_action`（无台词动作/氛围镜头）。只有 `dialogue` 才要求明确 `speaker`，并在下游分镜/视频中触发“可见说话主体、口型/讲话表情、非旁白”的强约束。
- 用户明确不希望直接大改正式代码链路，避免一通改造后反而让脚本、分镜图、视频质量下降；当前优先路线改为“影子测试 / 平行测试”：先不接正式 dispatcher/状态流/飞书写回，只额外做一个独立测试器，输入已有脚本，输出四类测试产物：1）结构化脚本 JSON；2）基于结构化结果生成的分镜提示词；3）基于结构化结果生成的视频提示词；4）markdown 测试报告。
- 约定的首轮测试操作方式：先准备 6 条样本脚本（2 条对白主导、2 条混合型、1 条旁白主导、1 条静默/氛围主导），放入测试输入目录；再由工程侧实现独立脚本（建议名如 `tk_toolkit_dual/test_structured_script_shadow_flow.py`），批量输出结构化结果与 prompts；用户先人工审查“该张嘴说话的句子是否被识别为 `dialogue`、分镜 prompt 是否清楚指定说话主体、视频 prompt 是否明确‘角色出镜说话而非旁白’”，通过后再只挑 3 条样本去试跑真实分镜图/视频。
- 本轮还形成了首版测试 prompt 设计方向：
  1. 结构化 prompt：把任意原始脚本拆为 `dialogue` / `voiceover` / `silent_action` 三类 segment，并输出统一 JSON schema；
  2. 分镜 prompt：对白段强制可见说话主体、面部/嘴部尽量可见，禁止用纯空镜承载对白；
  3. 视频 prompt：对白段明确要求画面内角色说出台词、自然口型和说话表情，不能退化成统一画外音。
